**你會學到：** 什麼時候自己管 VPS 會比 serverless 便宜、哪些工作適合 VPS、擴充、維護和安全上有哪些事要自己來，以及一間公司離開雲端的真實例子。

[伺服器程式在哪裡執行](/blog/running-server-code)的決策流程裡，有一題是：你想自己管作業系統嗎？這篇就是在回答這一題。VPS 是限制最少的選擇：你拿到一台 Linux 機器，其他全部自己決定。划不划算，要看流量多大、做的是什麼樣的工作，以及誰來照顧這台機器。它不會在每一方面都是最好的選擇。

## 成本要看流量

拿一支小型 API 來算：每個請求執行 100 ms，用 512 MB 記憶體。下面是它放在 AWS Lambda（x86、美東、透過 function URL 呼叫）和 DigitalOcean Droplet 上，每個月的費用。價格是 2026 年 11 月查的官方定價：

| 平均流量 | 每月請求數 | AWS Lambda | Droplet，1 vCPU／1 GiB |
| --- | --- | --- | --- |
| 每秒 0.1 個 | 26 萬 | $0（在免費額度內） | $6 |
| 每秒 1 個 | 260 萬 | $0.32 | $6 |
| 每秒 5 個 | 1,300 萬 | $6.53 | $6 |
| 每秒 10 個 | 2,600 萬 | $19.92 | $6 |
| 每秒 50 個 | 1.3 億 | $127 | $6 到 $18，前提是一台機器撐得住 |

Lambda 每一百萬個請求收 $0.20，每 GB-秒收 $0.0000166667，每個月免費額度是一百萬個請求和 40 萬 GB-秒。Droplet 不管流量多少都是同一個價錢：1 vCPU、1 GiB，每月 $6，包含 1,000 GiB 的對外流量。

以這支 API 來說，**整個月平均每秒大約 5 個請求**時，兩邊的費用差不多。流量比這少，serverless 比較便宜，side project 幾乎不用錢；比這多，固定價格的機器就比較划算，而且流量越大差越多。這張表有兩件事沒有算進去，而它們可能改變結論：一是資料傳輸費用（Lambda 照 EC2 的費率算，Droplet 在額度內免費），二是你自己花的時間，後面兩節會講到。

## 各種情境

| 情境 | 流量 | 通常比較適合 | 原因 |
| --- | --- | --- | --- |
| Side project 或內部工具 | 一天幾百個請求 | Serverless，或 PaaS 的免費方案 | 遠低於免費額度；VPS 就算閒著也要付錢 |
| 全天流量都很穩定的 API | 24 小時都是每秒 10 個請求 | VPS，或一直開著一份的 container 平台 | Lambda 每月大約 $20，Droplet 只要 $6，而且流量越大差越多 |
| 用 WebSocket 的聊天室或即時儀表板 | 上千條連線、一開就好幾個小時 | VPS 或 container 平台 | Serverless 的 WebSocket 到了時間上限就會斷（Vercel Functions：300 到 800 秒；AWS API Gateway：2 小時），要開好幾個小時的連線，放在伺服器上比較適合 |
| 搶票或新品發表 | 10 分鐘內每秒 2,000 個請求，之後幾乎沒有 | Serverless，或會自動擴充的 container 平台 | VPS 得照尖峰的量來準備，其他時間都在空轉；Lambda 預設最多同時執行 1,000 個，這次尖峰只需要 200 個，綽綽有餘 |
| 團隊裡沒有人管伺服器 | 任何流量 | PaaS 或 serverless | 更新修補、憑證和備份都要有人負責，沒人更新的 VPS 才是最大的風險 |

## 五個面向的比較

| | VPS | Serverless（AWS Lambda） |
| --- | --- | --- |
| 成本 | 每月固定；流量穩定之後最便宜 | 依請求數和 GB-秒計費；流量少或起伏大時最便宜 |
| 擴充 | 要自己動手。Droplet 升級規格要先關機，已用的磁碟每 GB 大約停機一分鐘，而且磁碟不能再縮小。要加機器，就得再加一個 load balancer | 自動擴充，預設每個 Region 最多同時執行 1,000 個；每個 function 每 10 秒可以多開 1,000 個 |
| 維護 | 作業系統更新、憑證更新、備份、重啟掛掉的 process、注意磁碟空間，都要自己來 | AWS 預設會自動更新 runtime 的安全修補；你只要維護自己的程式和依賴套件 |
| 安全 | 作業系統、更新修補和防火牆都是你的責任。AWS 的責任分擔模型裡，EC2 這幾項也是劃給客戶的 | 沒有作業系統或 SSH 要顧；你要負責的是權限、機密和自己的程式 |
| 控制權 | 完全自由：任何 process、任何 port、任何軟體、長時間的連線都行 | 要在平台的限制內：每次執行有時間上限、連線到時間就會斷、兩次請求之間不保留任何狀態 |

所以 VPS 划算的條件是：流量穩定，而且超過打平的那個點；工作需要一直在跑的 process，或一直開著的連線；而且有人負責更新修補。少了任何一項，把你自己的時間也算進去的話，託管的選擇通常比較便宜。

## 走得最遠的做法：離開雲端

有些公司走得比 VPS 更遠，直接用自己的硬體。Basecamp 和 HEY 背後的公司 37signals，在 2022 年 10 月宣布因為雲端帳單太貴，要把這兩個產品搬離 AWS 和 Google Cloud。現在它們跑在公司自己買的伺服器上，放在租來的機房裡。公司預估五年能省下超過 1,000 萬美元，並在 2025 年表示要刪掉 AWS 帳號，從此不用再付每年大約 150 萬美元的 S3 帳單（[The Register](https://www.theregister.com/2025/05/09/37signals_cloud_repatriation_storage_savings)、[DCD](https://www.datacenterdynamics.com/en/news/37signals-claims-it-saved-almost-2m-last-year-from-cloud-repatriation)）。這些都是公司自己公布的數字。

道理跟上面的表格一樣，只是規模更大：穩定、可以預期的流量，放在固定價格的機器上，會比依用量付費便宜，前提是要有一個團隊負責照顧這些機器。

> [!PRINCIPLE] 核心原則
> VPS 是用自己動手維護，換一張固定的帳單。流量穩定、工作需要一直開著的 process，而且有人負責更新修補時，選它就划算。
